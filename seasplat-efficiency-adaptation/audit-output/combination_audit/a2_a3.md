## ✅ The predicted conflict does not occur — but only by accident

The efficiency-adaptation framing anticipated that **"pruning invalidates the codebook"**:
if a codebook is fit over a population that is subsequently pruned, the centroids reflect a
distribution that no longer exists, and per-Gaussian assignments referencing removed indices
go stale.

**This cannot happen on A6.** Because A3 is post-hoc (`a3.md` A3-1), the codebook is
necessarily fit *after* every A2 prune has already run — the last reorg fires at iteration
30 000, `quantize.py` runs afterwards on the saved `.ply`. The ordering is safe **by
construction**, not by design.

### 🔴 C6-1 — Fixing A3-2 would create the predicted conflict

This is the important forward-looking finding. The recommended repair for A3 is to make it
quantization-aware, as compact3d requires (`a3.md` A3-2). **That repair introduces exactly
the conflict that is currently absent**, and the repair plan must account for it:

| compact3d mechanism | What A2's `prune_points` does to it |
|---|---|
| `nn_index` — per-Gaussian assignment vector, length `N` `[compact3d repo: kmeans_quantize.py:143]` | Length becomes stale on every prune. Must be index-selected alongside `_xyz`, `_opacity`, … inside `prune_points`. |
| Assignments refreshed every `t = 100` iterations `[compact3d §4]` | A2 prunes every **500** iterations. Between a prune and the next refresh, up to 100 iterations run against assignments computed for the pre-prune population. |
| Centroids updated **every** iteration from cached indices `[compact3d repo: kmeans_quantize.py:46-61]` | Uses the stale index vector directly — this is the path that would break first. |
| Codebook size `K` fixed | After pruning, clusters may empty out; `K` no longer reflects the population. compact3d never faces this because it keeps `reset_opacity()` and does not prune outside densification `[compact3d: 01-taxonomy.md]`. |

**Minimum requirement if A3 is made quantization-aware:** extend `prune_points` to carry
`nn_index`, and force an assignment refresh immediately after every `reorganize_gaussians`
call. Cadence alignment (`t = 100` vs prune interval 500) should be made explicit rather than
left to chance.

Note that compact3d's own count-reduction mechanism (ℓ1 opacity regularizer + periodic
pruning in the 15 K–20 K window) *does* coexist with its QAT — so this is a solved problem
upstream, and the solution is available to copy `[compact3d repo: train_kmeans.py:158-166]`.

## 🟢 C6-2 — A2 mildly reduces A3's opacity-quantization risk

`a3.md` A3-3 flags that quantizing opacity risks snapping near-threshold Gaussians back
above the α ≈ 0.005 visibility boundary. On A6, A2 has already removed the lowest
`opacity × scale` Gaussians before the codebook is fit, so the opacity distribution reaching
K-means is **truncated from below**. Fewer Gaussians sit near the boundary, and K-means
spends fewer of its 256 centroids on the near-zero tail.

The effect is real but modest, and it is conditional on A2 actually firing (`a2.md` A2-4).

## 🟡 C6-3 — The two mechanisms optimize different objectives with no shared budget

A2 reduces **count**; A3 reduces **bits per primitive**. compact3d observed that these are
not independent: after quantization, the unquantized attributes dominate, so count reduction
becomes the only remaining lever `[compact3d §3]`. That logic applies here with force —
`a3.md` A3-7 computes A3's ceiling at ≈ 2.8×, with protected `xyz` at 60% of the residual.

**A6 is therefore the combination where the compression story is most coherent**, because
A2's count reduction attacks precisely the term A3 cannot. But nothing in the code
coordinates them: `max_gaussians` and `k` are set independently, with no rate target and no
rate–distortion trade-off. (`my-research/CompGS/` — Liu et al. — is the method in the set
that puts a rate term `λR` in the loss; neither A2 nor A3 does.)

Practical consequence: **report A6's size as `count × bits`, and attribute the two factors
separately.** Otherwise A2's count reduction will be silently credited to the quantizer.
