```python
def get_importance(self, imp_metric='outdoor'):
    with torch.no_grad():
        opacity = self.get_opacity.squeeze(-1)
        if imp_metric == 'outdoor': scale = torch.max(self.get_scaling, dim=1).values
        else:                       scale = self.get_scaling.mean(dim=1)
        return opacity * scale

def reorganize_gaussians(self, max_gaussians, imp_metric='outdoor'):
    n_current = self.get_xyz.shape[0]
    if n_current <= max_gaussians: return 0
    importance = self.get_importance(imp_metric)
    _, idx = torch.sort(importance)                 # ascending
    prune_mask = torch.zeros(n_current, dtype=torch.bool, device='cuda')
    prune_mask[idx[:n_current - max_gaussians]] = True
    self.prune_points(prune_mask)
    return n_current - max_gaussians
```

## Fidelity to Mini-Splatting

**This is not Mini-Splatting.** It is a magnitude-based top-k prune wearing Mini-Splatting's
vocabulary. Component by component:

| Mini-Splatting component | A2 | |
|---|---|---|
| **Blur split** — split Gaussians with large projected area | ❌ absent | 🔴 |
| **Depth reinitialization** — resample primitives from rendered depth | ❌ absent | 🔴 |
| **Intersection preserving** — retain `G^int`, the Gaussians a ray actually intersects | ❌ absent | 🔴 |
| **Importance = accumulated blending weight** (`I¹`/`I²`, integrated over training views) `[mini-splatting §3.2]` | **`opacity × scale`** — an instantaneous, view-independent parameter magnitude | 🔴 **different quantity** |
| **Importance-weighted *stochastic* sampling** — sample without replacement ∝ importance `[mini-splatting §4.2]` | **deterministic ascending sort, prune the bottom `n`** | 🔴 **the approach Mini-Splatting argues against** |
| `imp_metric ∈ {outdoor, indoor}` selecting `I¹` vs `I²` (blending-weight power) | `imp_metric ∈ {outdoor, indoor}` selecting `max` vs `mean` over the 3 scale axes | 🔴 **same name, unrelated semantics** |
| `reset_opacity()` removed | ⚠️ retained (baseline behaviour) | 🟡 |

### 🔴 A2-1 — The importance metric is not Mini-Splatting's

Mini-Splatting's contribution *is* the metric: importance is the blending weight a Gaussian
actually accumulates across training views, so a large-but-occluded Gaussian scores low and a
small-but-frequently-visible one scores high. A2's `opacity × scale` is computed from stored
parameters alone. It has **no view term, no occlusion term, no visibility term**. A large
Gaussian buried inside geometry and never rasterized scores identically to one covering
half of every frame.

The docstring cites Mini-Splatting; the code does not implement it. **Cite this branch as
"magnitude-based pruning," not as Mini-Splatting**, or the thesis makes a claim the code
does not support.

### 🔴 A2-2 — Deterministic top-k is the failure mode Mini-Splatting names

Mini-Splatting §4.2 argues explicitly for *stochastic* importance-weighted sampling on the
grounds that deterministic top-k collapses primitives onto high-importance regions and
strips coverage from low-importance but still-necessary ones. A2 implements exactly the
deterministic variant. Under a 3D scene this concentrates survivors in high-opacity,
large-scale regions and can leave thin/distant structure unrepresented — with no
densification left to recover it on the A4/A7 branches.

### 🟢 A2-3 — But `opacity × scale` interacts *well* with SeaSplat, by accident

`self.get_opacity` is post-`L_op`. SeaSplat's opacity prior (λ = 0.01) actively drives
`α → 0` for Gaussians whose rendered contribution is backscatter-only
`[my-research/seasplat/…/04-loss.md]`. So `opacity × scale` ranks **medium-suppressed
Gaussians lowest**, and A2 prunes them first.

This is a genuine positive: A2 supplies precisely the removal mechanism that SeaSplat's
`L_op` needs and that **A1 destroys** (see `a1.md` A1-1). It is serendipity rather than
design — nothing in the code or the empty `docs/` shows the interaction was intended — but
it is the strongest efficiency-side result in the branch set, and it should be stated and
tested deliberately rather than left implicit.

## Timing analysis vs. `seathru_from_iter` — ✅ compliant

| Event | Iteration |
|---|---|
| Densification window ends (`densify_until_iter`) | 15 000 |
| Medium model activates (`seathru_from_iter`, README recipe) | 10 000 |
| **First A2 reorg** (`> 15000` and `% 500 == 0`) | **15 500** |
| Subsequent reorgs | every 500 → **30 events** through 30 000 |

**A2 fires strictly after the medium model is active**, so every importance score is
computed on a Gaussian population that has already co-adapted with `β^D`, `β^B`, `B^∞`.
This is the correct ordering, and it is the reason A2-3 works: pruning *before*
`seathru_from_iter` would have used opacities that `L_op` had not yet shaped, and would have
removed Gaussians that the medium model would later have explained.

**It also never overlaps densification** (`> densify_until_iter` vs `< densify_until_iter`),
so there is no add/remove thrash.

⚠️ Caveats, both traceable to the empty `docs/experiment_plan.md`:

- `seathru_from_iter` **defaults to `9_000_000`** `[repo: arguments/__init__.py:179]`. If the
  runs were launched without the flag, the medium model never activated, A2-3 does not hold,
  and the entire comparison is against plain 3DGS. **The actual value used is unrecorded.**
- The `> densify_until_iter` coupling is implicit. Raising `densify_until_iter` silently
  delays A2; setting `seathru_from_iter > 15000` would silently invert the ordering and put
  A2 *before* the medium model. Nothing guards against this.

> `c^med` predicted by an MLP), a population edit would have no such guarantee. See

## 🟡 A2-4 — The budget is probably non-binding, and unmeasured

`max_gaussians = 800_000`. `reorganize_gaussians` returns `0` immediately when
`n_current <= max_gaussians`, so **if SeaSplat's underwater scenes never reach 800 k
Gaussians, A2 is a no-op and the branch is baseline with extra logging.**

SeaSplat does not report Gaussian counts anywhere in the paper
`[my-research/seasplat/…/08-computational-profile.md]`, and `docs/` is empty, so there is no
recorded evidence either way. The `[A2] Reorg @ iter …` print and the `a2/gaussians`
TensorBoard scalar would settle it in one run — **but only fire when pruning actually
happens**, so a silent log is ambiguous between "no-op" and "not run."

**This is the highest-value cheap check in the whole audit**: if A2 never triggers, then
A2, A4, A6 and A7 are all partly or wholly mislabelled, and four of the eight factorial
cells collapse. Log `n_current` unconditionally.

## 🟡 A2-5 — The `hasattr` guard is vacuous

`hasattr(opt_params, 'max_gaussians')` is **always `True`**, because the same branch adds
`self.max_gaussians = 800_000` to `OptimizationParams`. The paired
`getattr(opt_params, 'max_gaussians', 800_000)` default is likewise dead. The apparent
opt-in is not one: **there is no flag that disables A2**, so the branch cannot reproduce
baseline for a control run. Setting `--max_gaussians` to a very large number is the only
workaround. Cosmetic in effect, misleading in intent.
