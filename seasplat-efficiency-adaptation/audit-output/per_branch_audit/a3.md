## 🔴 A3-1 — The mechanism is never wired into training

`train.py` is **untouched on this branch** (`+0 / −0`; `grep -n 'quant|Quant|source\.'`
returns nothing). `source/quantize.py` is a **standalone offline script with its own
`argparse`**, run manually after training against a saved `point_cloud.ply`.

Meanwhile `arguments/__init__.py` gains three parameters —

```python
self.quant_k          = 256
self.quant_group_size = 4
self.quant_xyz        = False
```

— which **are read by nothing**. `quantize.py` declares its own identical CLI defaults
(`--k 256`, `--group_size 4`, `--quant_xyz`). The `arguments/` entries are dead config that
signal an intended in-loop integration that was never completed. Anyone reading
`arguments/__init__.py` will reasonably conclude A3 runs during training. It does not.

**This single fact reframes the whole branch**, and everything below follows from it.

### 🔴 A3-2 — Post-hoc quantization is the failure mode compact3d exists to avoid

compact3d's entire contribution is that quantization must happen **during** training so the
non-quantized parameters can adapt, via STE, to the centroids they will be snapped to
`[compact3d §3, verified at repo kmeans_quantize.py:194,204]`. A3 snaps a finished model with
**no recovery step**. Whatever distortion K-means introduces is the final distortion.

Under plain 3DGS that costs some PSNR. Under **SeaSplat** it is worse, because two of
SeaSplat's losses shape exactly the attributes being snapped:

| Loss | Acts on | Post-hoc quantization effect |
|---|---|---|
| `L_gw` (grey-world, λ = 0.1, gated to `iter > seathru_from_iter`) | mean colour of the restored image `Ĵ` | `f_dc` snapping perturbs the aggregate colour statistic `L_gw` spent 20 000 iterations balancing. **No gradient step follows to rebalance it.** |
| `L_sat` (saturation, λ = 2.0) | caps `Ĵ` at 0.7 | Snapping can push individual `f_dc` values back above the cap. |
| `L_op` (opacity prior, λ = 0.01) | drives `α → 0` for backscatter-only Gaussians | see A3-3 |

`L_gw` and `L_sat` are the losses that make SeaSplat's restoration look colour-corrected
rather than blue-green. A post-hoc perturbation of `f_dc` degrades **restoration quality**
specifically — and, being a global colour shift, it is the kind of error that PSNR against a
*raw underwater* GT will barely register. **The metric will under-report this damage.**

### 🔴 A3-3 — Opacity is quantized; compact3d excludes it, for stated reasons

`to_quantize = ['f_dc', 'f_rest', 'opacity', 'scale', 'rotation']`. compact3d deliberately
leaves opacity in float32.

The stored value is the **logit** `_opacity`, not `α`, which bounds the damage: the long
negative tail (α ≈ 0) is spread over many logit units, so centroids in that region cause
large *logit* error but negligible *α* error. The real exposure is at the decision boundary —
Gaussians sitting just under the α ≈ 0.005 visibility threshold that `L_op` pushed there can
be snapped to a centroid above it, **re-materializing floaters that SeaSplat's opacity prior
had specifically suppressed.**

With `k = 256` over a 1-D attribute, the resolution is actually generous and the risk is
moderate rather than severe. The finding is less "this will definitely break" than
**"this is an unmotivated deviation from a source method that excluded this attribute on
purpose, in a codebase whose opacity semantics are load-bearing."** It costs almost nothing
to fix (drop one string from a list; opacity is 1 of 14 floats).

⚠️ **On the A5 and A7 branches this compounds with A1**, where the α-prune is disabled and
those suppressed Gaussians are still present in the `.ply` to be re-materialized. See
`combination_audit/a1_a3.md`.

## Implementation details

### 🟡 A3-4 — `group_size = 4` is inert at `sh_degree = 0`

SeaSplat runs at `sh_degree = 0`, giving 14 floats per Gaussian: `xyz` 3, `f_dc` 3,
`opacity` 1, `scale` 3, `rotation` 4 `[my-research/seasplat/…/03-variables.md]`. With
`n_groups = ceil(D / 4)`:

| Attribute | `D` | groups |
|---|---|---|
| `f_dc` | 3 | 1 (padded to 4) |
| `opacity` | 1 | 1 (padded to 4) |
| `scale` | 3 | 1 (padded to 4) |
| `rotation` | 4 | 1 |
| `f_rest` | **0** | skipped ✅ |

**Every attribute is a single group.** The grouping machinery is dead code at the
configuration actually in use, and would only activate at `sh_degree > 0`. Not a bug —
zero-padding adds a constant column that does not perturb K-means distances — but the
parameter gives a false impression of tunability.

### 🟡 A3-5 — `uint16` indices waste 2× on a 256-entry codebook

`idx = km.labels_.astype(np.uint16)` with `k = 256` needs only 8 bits. This exactly mirrors
compact3d's own index-width defect (`ceil(log2(N))` instead of `ceil(log2(K))`,
`[my-research/compact3d/…/11-paper-vs-repo-disagreements.md, D-4]`) — an inherited-by-accident
bug, not a copied one.

### 🟡 A3-6 — The compression ratio conflates VQ with zlib

Reported as `orig_ply_mb / npz_mb`, where the NPZ is written with
**`np.savez_compressed`** — zlib on top of quantization. compact3d reports raw bit-packed
size. **The two numbers are not comparable**, and A3's figure credits generic entropy coding
to the quantizer. Report the raw quantized size alongside it.

### 🟡 A3-7 — Achievable compression is structurally capped near ~3×

`[inferred]` arithmetic at `sh_degree = 0`, per Gaussian:

| | bytes |
|---|---|
| Original (14 × float32) | 56 |
| Quantized: `xyz` float32 (12) + 4 × `uint16` index (8) | **20** |
| → raw ratio | **≈ 2.8×** |
| with `uint8` indices (A3-5 fixed) | 16 → ≈ 3.5× |

Codebooks are negligible (4 × 256 × ≤4 floats). Against compact3d's reported **40–50×**,
A3 is an order of magnitude short — and the reason is exactly the one compact3d identified:
**protected `xyz` dominates the residual** (12 of 20 bytes, 60%). compact3d responded by
reducing the *count*; its successors (`my-research/OMG/`, `my-research/CompGS/`) responded
with G-PCC position coding. A3 does neither, so ~3× is its ceiling regardless of `k`.

**This is the finding most likely to affect the thesis's headline claim.** If A3 is reported
as an attribute-compression contribution, the achievable number should be stated as ~3×
before the runs, not discovered after.

## Timing analysis vs. `seathru_from_iter` — n/a, and correctly so

A3 has **no in-loop schedule**; it runs after training terminates. There is therefore no
ordering relationship with `seathru_from_iter` at all — the one mechanism of the three that
cannot possibly conflict with the medium model's activation.

### ✅ A3-8 — Medium-model handling is correct and explicit

`quantize.py` prints `SeaThru backscatter/attenuate .pth untouched` and
`Protected models: backscatter .pth attenuate .pth`, and writes **two** artifacts:

| Artifact | Purpose |
|---|---|
| `--out_npz` | the compressed representation (codebooks + indices) |
| `--out_ply` | **dequantized reconstruction, for evaluation with `render_uw.py`** |

This is the right design. The medium parameters live outside the PLY in separate
`nn.Module` checkpoints, so the evaluation path — reconstructed `.ply` + original `.pth` —
renders through SeaSplat's full underwater model with the quantization damage present and
the medium model intact. **A3 is the only branch that documents its own interaction with
the medium model, and it gets it right.**

One accounting caveat: the `.pth` files are excluded from **both** sides of the ratio. At 9
scalars this is immaterial, but it should be stated rather than left implicit.

## Gradient-path analysis — n/a

A3 introduces no gradients, no losses, and no parameters into training. Nothing to audit.
This is a direct consequence of A3-1: post-hoc means gradient-free means also
**recovery-free**, which is the whole problem.
