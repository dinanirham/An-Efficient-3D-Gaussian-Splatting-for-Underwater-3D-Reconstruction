## 🔴 The load-bearing finding: `--no_densify` disables pruning and opacity reset too

In SeaSplat's `train.py` the gated block contains **three** mechanisms, in both the
freeze and unfreeze sub-branches:

```
if iteration < opt_params.densify_until_iter:          # ← A1 adds `not no_densify and`
    ...
    gaussians.max_radii2D[...] = ...                   # radii tracking
    gaussians.add_densification_stats(...)             # gradient accumulation
    if iteration % densification_interval == 0:
        if iteration > densify_from_iter:
            gaussians.densify_and_prune(τ, 0.005, ...)  # ← densify AND α<0.005 prune
    if iteration % opacity_reset_interval == 0 ...:
        gaussians.reset_opacity()                       # ← opacity reset
```
`[repo: train.py:517-547]`, `opacity_reset_interval = 3000` `[repo: arguments/__init__.py:100]`

Setting `--no_densify` therefore removes **densification, α-pruning, and opacity reset
simultaneously**. Consequences, in order of severity:

1. **The Gaussian count is frozen for all 30 000 iterations.** Whatever `roma_init.py`
   produces is exactly what is rendered and saved. The count is set by `voxel=0.001`,
   `matches`, and `nns` — three offline parameters — and is never subsequently corrected.

2. **🔴 SeaSplat's `L_op` is left with no executor.** SeaSplat's opacity prior
   (`λ_op = 0.01`) exists specifically to drive `α → 0` for Gaussians whose rendered
   contribution is backscatter-only, i.e. `Î ≈ B^∞`
   `[my-research/seasplat/…/04-loss.md]`. In baseline SeaSplat those suppressed Gaussians
   are then **removed** by the `min_opacity=0.005` argument to `densify_and_prune`. Under
   `--no_densify` they are suppressed but **never removed**. The model accumulates a
   population of α ≈ 0 primitives that:
   - cost memory and per-frame sort/rasterize time (the efficiency claim is directly harmed);
   - are written to the `.ply`, inflating the reported model size;
   - contribute nothing to PSNR, so the fidelity metric will **not reveal the problem**.

   This is the single most consequential deviation on the branch: **the mechanism A1 breaks
   is the one SeaSplat added on top of 3DGS**, and the metric being reported cannot see it.

3. **Opacity reset is gone.** EDGS also disables reset — but *deliberately*, replacing it
   with the continuous `×0.99` decay (F-2) and keeping the cull. A1 removes reset and
   supplies **neither** replacement. This is a removal by side-effect, not by design.

4. Radii tracking and `add_densification_stats` also stop. Harmless — they only feed
   densification — but it means `max_radii2D` is stale if any later code reads it.

**Predicted risk vs. observed.** The efficiency-adaptation framing anticipated that dense
initialization would need care around *count control*. The actual failure mode is narrower
and more specific: not that the count is too high at init, but that **the count cannot go
down at all, and SeaSplat's medium-aware opacity suppression is thereby rendered inert.**
That is a more serious finding than predicted, and it is invisible to the current metrics.

## Timing analysis vs. `seathru_from_iter`

**A1 has no in-loop schedule.** Its two effects are (a) at `t = 0` (initialization) and
(b) a whole-run gate. So there is no ordering conflict with the medium model in the
usual sense. But two timing interactions are real:

| Interaction | Assessment |
|---|---|
| Init at `t=0` vs. medium activation at `seathru_from_iter` | 🟢 **Safe.** Geometry is seeded before the medium model exists, matching baseline ordering. Iterations `[0, seathru_from_iter)` optimize clean-image geometry only. |
| `no_densify` gate spans `[0, densify_until_iter = 15000)`, which **straddles** `seathru_from_iter` | 🟡 In baseline, densification continues for 5 000 iterations *after* the medium model activates (at 10 000, per the README recipe), letting geometry adapt to the newly-explained backscatter. A1 removes that adaptation window entirely. Any geometry error that only becomes visible once `B^∞` is being modelled has no way to be corrected by adding primitives. |

⚠️ **`seathru_from_iter` defaults to `9_000_000`** `[repo: arguments/__init__.py:179]` — i.e.
**the medium model is off unless explicitly enabled on the CLI**, exactly the "defaults
disable the method" trap catalogued for compact3d
`[my-research/compact3d/…/11-paper-vs-repo-disagreements.md, D-6]`. The value actually used
is **not recorded anywhere in this repo** (`docs/experiment_plan.md` is 0 bytes). Every
timing claim above assumes the README recipe value of 10 000. See `open_questions.md` Q-3.

## Gradient-path analysis

| Path | Status |
|---|---|
| `scene_info._replace(point_cloud=...)` runs **before** `create_from_pcd` | ✅ Correct insertion point. Feeds `_xyz`, `_features_dc`, `_scaling` (from nearest-neighbour distances) exactly as the COLMAP path would. No autograd involvement — this is pre-optimizer construction. |
| Colour fallback `cols = np.full_like(pts, 0.5)` when the PLY has no colours | 🟡 Seeds every `_features_dc` at mid-grey. Under SeaSplat this is **not neutral**: `L_gw` (grey-world, λ=0.1) and `L_sat` (λ=2.0) both act on the restored image `Ĵ`, and a uniform-grey init sits exactly at `L_gw`'s fixed point. Harmless if `roma_init.py` always writes colours (it samples them from the source images), but the fallback path would silently produce a degenerate colour prior. Low probability, high confusion value. |
| The three optimizers | ✅ Untouched. A1 adds no parameters and no losses. |
| `no_densify` and autograd | ✅ No direct gradient effect — `densify_and_prune` / `reset_opacity` run under `torch.no_grad()` and rebuild optimizer state. Disabling them changes *which* parameters exist, not how gradients flow to them. |
| Medium parameters (`β^D`, `β^B`, `B^∞`) | ✅ Untouched. They are 9 globals held in separate `nn.Module`s with their own optimizer, structurally immune to changes in the Gaussian population. |

**No gradient-path defect found.** A1's problems are all population-management problems.
